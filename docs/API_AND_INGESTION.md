# API and Ingestion

The API is versioned under `/api/v1`; `/openapi.json` is generated by FastAPI.

## Authentication

- UI: local email/password creates an HttpOnly, SameSite session plus a double-submit CSRF token.
- SDK/ingestion: workspace API keys use `Authorization: Bearer ve_...`; only their SHA-256 digest is stored.

API keys are displayed once. Never put them in source control or browser storage.

## Canonical ingestion

`POST /api/v1/ingestion/conversations` requires a canonical `ConversationTrace` and an `Idempotency-Key`. `POST /api/v1/ingestion/conversations/batch` accepts up to 1,000 items and reports per-item success/failure.

Original utterance text is stored unchanged. Optional translations are reviewer aids. Retrieval and tool evidence reference stable turn/source/definition IDs. A repeated external conversation or idempotency key with different content is rejected with `409`.

Upsert agent, immutable configuration, knowledge, and tool definition versions before ingesting traces that reference them. The complete shape is available in OpenAPI and `packages/schemas`.

## Integration maturity

- Level 1: transcript/config only—response, conversation, and some grounding evals.
- Level 2: adds retrieval/knowledge—RAG and stronger grounding evals.
- Level 3: adds tool definitions/calls/results—complete tool trajectory evals.

Missing evidence yields `NOT_APPLICABLE`; it is never converted into a fabricated score.

## Webhooks and external platforms

External systems should send signed/authenticated requests through a workspace API key. Normalize vendor payloads in a read-only connector before calling ingestion. Core evaluation code only consumes canonical schemas.
